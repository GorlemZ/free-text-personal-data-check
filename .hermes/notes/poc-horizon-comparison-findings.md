## Condivisione del PoC — 2026-11-09
- La motivazione dell'API è **comparabilità end-to-end tra due runtime diversi**, non una decisione generale contro le librerie: il codice Python e quello Node espongono lo stesso contratto al runner. L'HTTP include il suo overhead e sposta il testo nella richiesta; l'uso in-process potrebbe ridurre il costo di trasporto in un singolo runtime ma non riprodurrebbe il confronto attuale. Autenticazione, rete fidata e telemetria senza payload sono condizioni per un'integrazione futura, non proprietà già presenti.
- La root confondeva test specifici dei motori, test automatici del runner e corpus/benchmark Docker; `comparison/tests/` e il relativo README separano i livelli, mantenendo il corpus annotato in `comparison/corpus.json` e il runner reale in `comparison/run.mjs`. I test di confronto non certificano accuratezza o stabilità.
- La documentazione del runner descriveva `--memory=4g --memory-swap=4g` come “swap=RAM”: quei due valori uguali non lasciano quota swap al container. La build Horizon richiede `npm run prefetch` perché il Dockerfile copia `models/` e ne verifica il manifest; entrambi i prerequisiti sono ora espliciti. Il README Horizon descriveva ancora come futura la suite condivisa già presente: allineato.
- Review indipendente dei README/test: il benchmark di memoria **è stato ripetuto dopo il CF** (due serie × 1.000 per motore, RSS massime campionate Horizon 1598,4/1602,8 MiB, spaCy 184,9/184,9 MiB); non presentare come unico il risultato precedente. Lo staging parziale delle sole rinomine avrebbe lasciato import non aggiornati: prima di qualsiasi commit l'indice deve includere import corretti e guida. `poc-horizon/package.json` richiede Node.js ≥22; ora esplicitato nei comandi.
